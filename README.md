# Personal Money Projection

从工资条到长期投资的个人财务投影工具。支持**中国 / 美国 / 加拿大**三地税制，界面中英双语。
税与强制缴款按国家和辖区精算，结果同时给出**名义金额**与**今日购买力**两个口径，
并用**分布**而不是单条曲线来表达不确定性。

前身是 [`docs/legacy/money-calculator.html`](docs/legacy/money-calculator.html) —— 一个 11KB 的单文件页面，作为对照基准保留。

## 相比原型页面补上了什么

| 原型页面的问题 | 现在的做法 |
|---|---|
| 输入 7% 就当真每年涨 7%，单条确定性曲线 | 蒙特卡洛 P10–P90 扇形分布 + 亏损概率 |
| 综合所得税率表**只到 30%**，缺 35% / 45% 两档 | 七档齐全，高收入不再被系统性少算 |
| 年终奖固定按 10% 档计税（`bonus*.10-210`） | 按 `奖金/12` 查月度税率表，并与「并入综合所得」逐年自动择优 |
| **完全没有专项附加扣除** | 6 项齐备（子女教育 / 婴幼儿 / 继续教育 / 住房 / 赡养老人），一年可差十万量级的扣除额 |
| 社保写死 10.5%、公积金写死 12%，无缴费基数上下限 | 9 个城市的基数上下限与费率，且全部可按工资条覆盖 |
| 工资与开销 40 年恒定 | 年涨薪率 + 升职跳变；开销通胀 |
| 没有通胀口径 | 每个结果都有名义 / 今日购买力两个口径，一键切换 |
| 忽略跨境摩擦 | 基金费率、股息预扣税；超出 5 万美元购汇额度时提示 |
| 公积金净额可以算成负数并按负数外推 20 年 | 余额守恒、1.5% 结息、提取受余额约束 |
| 刷新即失忆 | 本地自动存 + URL 分享 + 可选的云端账号同步 |
| 财务计算无任何测试 | 127 项单元测试，重点覆盖三国税率临界点与蒙特卡洛的统计性质 |
| 只有中国、只有中文 | 中/美/加三地税制，中英双语 |

界面语言支持简体中文与英文，与货币格式**正交**——中国用户可以用英文界面看人民币。

## 架构

```
packages/engine    纯 TypeScript 计算引擎，零运行时依赖，127 项 Vitest 测试
  tax/             通用累进税率与抵免计算
  regions/cn|us|ca 各国税制实现，全部实现同一个 RegionModule 接口
  regions/registry 地区注册表，通用流程只通过它取实现
packages/shared    Zod schema —— 前端表单校验 / 后端入参校验 / URL 编解码，一处定义
apps/api           Hono + Prisma + PostgreSQL + Better Auth
apps/web           Vite + React + TypeScript（i18n 在 src/i18n/）
```

**地区抽象**：所有国别差异都收敛在 `RegionModule` 接口后面，时间轴、投资、通胀这些通用流程
与国家无关。加第四个国家只需新增一个 `regions/xx/` 目录并注册，不动任何通用代码。

**引擎不产出自然语言**：警告是结构化的 `{ code, params }`，翻译发生在 UI 层。
这是多语言能成立的前提——否则警告文案会永远锁死在一种语言里。

引擎是一个纯函数 `ProjectionInput → 逐月状态数组`。UI 只负责渲染，服务端只负责存取。
这样才能写单测、才能在浏览器里跑 2000 条蒙特卡洛路径、才能把参数编码进 URL。

**本地优先**：`localStorage` 始终是事实来源。不登录、断网、甚至把单文件构建产物拷走双击打开，功能都完整；
云端同步是叠加在其上的备份层，不是运行前提。

## 快速开始

```bash
pnpm install
cp .env.example .env          # 同样的变量也要放一份到 apps/api/.env
pnpm db:up                    # Docker 起 PostgreSQL（映射到 5433，避开本机已有的 5432）
pnpm db:migrate               # 建表
pnpm dev                      # 前端 :5173，API :8787
```

只想要计算器、不需要账号同步的话，跳过 `db:up` / `db:migrate`，直接 `pnpm dev:web` 即可。

## 数据与隐私

方案以**关系化明文**存在 Postgres 里（不是加密 blob），换来的是服务端可查询、可聚合、
未来可做跨方案对比的能力。保护手段是 TLS、磁盘加密和 API 授权，而不是密码学——
所有查询都强制带 `userId` 条件，越权访问一律返回 404 而不是 403，避免泄露资源是否存在。
密码由 Better Auth 哈希，本项目任何地方都不接触明文。

如果你更看重隐私上限，可以改成端到端加密：把 `Scenario` 换成 `ciphertext Bytes` 单列，
在浏览器里用 WebCrypto 加密后再上传。代价是忘记密码即丢数据，且服务端侧功能全部要挪到客户端。

## 数据来源与更新机制

**三个国家都没有官方的税率 API。** 税率表由立法和行政公告发布（IRS Rev. Proc.、CRA 网页、
各地人社局年度公告），不是数据服务。所以这里做的不是"实时数据源"，而是一套
**让数据永远不会被静默地用旧**的机制。

| | 上游 | 自动化程度 |
|---|---|---|
| 🇺🇸 美国联邦 | [PolicyEngine/policyengine-us](https://github.com/PolicyEngine/policyengine-us) —— 按生效日期分版本、带法条引用的 YAML | ✅ `pnpm data:sync` 全自动 |
| 🇺🇸 美国州级 | 同上。各州 YAML 布局不统一，但归纳为三种模式即可覆盖 | ✅ 19 州自动同步；OH 刻意排除、MA 结构特殊，保持手工 |
| 🇨🇦 加拿大联邦 | [PolicyEngine/policyengine-canada](https://github.com/PolicyEngine/policyengine-canada) | ✅ `pnpm data:sync` 全自动 |
| 🇨🇦 加拿大省级 | 同上，但**上游停留在 2022–2023 年，比本仓库还旧** | ⚠️ 手工维护，同步脚本会主动警告不要采信上游 |
| 🇨🇳 中国 | 无。国家统计局 easyquery 对自动化访问返回 `403 UrlACL` | ❌ `pnpm data:check:cn` 变更检测 + 人工核对 |

### 四条命令

```bash
pnpm data:sync     # 从 PolicyEngine 拉美加可自动化的参数（加 --write 才写文件）
pnpm data:audit    # 遍历全部 31 个数据集，任何一项过适用期就非零退出
pnpm data:check    # 检测无上游的官方页面有无变动（中国人社局 + 加拿大 CRA）
pnpm data:verify   # 把同一批家庭喂给本引擎和 PolicyEngine 实时 API，比对结果
```

### 「保证一直最新」做不到，「过期一定被发现」做得到

这是整套机制的核心取舍，值得说清楚：

三个国家都没有官方数据接口。能同步的已经同步了（美国联邦 + 19 个州、加拿大联邦）；
剩下的 **27 个数据集没有任何可自动化的源**——中国全部省级基数、
加拿大 CPP/EI 与省级分档、美国两个州及各州标准扣除。

所以 `data:audit` 换了个目标：不承诺数据永远新，而是**保证它一旦过期就一定会被发现**。
每个数据集都登记了适用期；[data-sync.yml](.github/workflows/data-sync.yml) 每周跑一次审计，
过期就自动开 issue 盯人，直到有人去核对。PR 上只警告不阻断——数据过期是维护节奏问题，
不该挡住无关的代码改动。

对中国而言，日历比爬虫更可靠：社保年度每年 7 月 1 日切换、公告集中在 7–8 月发布，
所以「适用期到期」本身就是最准的触发信号。人社局首页的指纹检测噪音太大，仅作参考。

### 人工更新靠恒等式把关

没有上游的数据只能人工抄，抄错一位数不会有任何报错——除非有恒等式。
例如加拿大的 CPP/EI：

```
CPP 最大缴款  = (YMPE − 基本免征额) × 费率
CPP2 最大缴款 = (YAMPE − YMPE) × 第二级费率
EI  最大保费  = 最高可保收入 × 费率
```

这些关系写成了测试。每年从 CRA 抄完新数字，跑一遍测试就知道抄没抄对。

`data:verify` 是最有价值的一条：同步只能保证"数字抄对了"，差分验证才能抓住
"算法用错了"。当前结果：

- 联邦税在 $45k/$90k/$180k 三档、所有州**完全相等**
- 州税：宾州四档全部精确相等，纽约 $45k/$90k 精确相等，德州（无州税）为 0
- 剩余差异全部是**建模范围**而非数据陈旧：加州的个人免税额抵免（固定约 $150，
  低收入时占比显眼）、纽约高收入的补充税追回、$400k 时 PolicyEngine 建模的
  SALT 分项抵扣（德州无州税故仍完全相等，正好反证了这一点）

### 不要盲目采信上游

同步脚本会主动警告两类陷阱，都是实际踩到过的：

1. **上游自己也会过期**——PolicyEngine 的加拿大省级数据停留在 2022–2023 年，
   比本仓库手工核对的还旧。脚本检测到就标红「不要采信」。
2. **上游可能编码了它自己的实现技巧**——俄亥俄的第一档税率在上游是 `0.0127448`，
   但那不是真实税率，而是为模拟「跨档时加收固定额」反推的隐含平均税率。
   当成普通边际税率从 0 起征的话，年收入 2 万的俄亥俄人会被算出 254 美元税，
   而法定应为 0。因此俄亥俄**刻意排除在同步之外**。

[.github/workflows/data-sync.yml](.github/workflows/data-sync.yml) 每周跑一次这三条命令，
有变更就自动开 PR，**但不自动合并**——上游自己也会过期，需要人判断。

### 数据永远不会被静默使用

每个辖区的数据都带 `Provenance`：适用期、来源 URL、核对日期、可信度。
引擎在数据过期或未核对时会产出结构化警告，界面上有醒目的数据口径徽标。

**「数据旧」和「建模不全」是两个维度，分开表达**：适用期（`effectiveTo`）管前者，
可信度（`confidence`）管后者。所以加州显示「已同步、但建模不全（estimated）」，
宾州显示「完全干净（derived）」，俄亥俄显示「已过期」——三种状态各有各的含义。

一个财务工具最容易骗人的地方不是算错，而是拿两年前的参数算得一丝不苟。

## ⚠️ 关于数据准确性

- **城市社保参数是近似默认值**，来自 2024–2025 社保年度的公布数据。基数上下限每年随社平工资调整，
  公积金比例各单位也不同。请对照你的工资条核对——界面上每个参数都能直接改。
- **年终奖单独计税政策延续至 2027-12-31**。政策若不再延期，请关掉界面上的对应开关。
- 月度税额按年度税额均摊展示，与实际的累计预扣法逐月不均有差异，但全年合计一致。
- 蒙特卡洛分位数是同一组假设下的模拟分布，**不是预测，更不是收益承诺**。
- 汇率波动、投资端资本利得税、债务与房贷、失业与重疾等中断，均未纳入模型。

本工具仅供个人规划参考，不构成投资建议。
